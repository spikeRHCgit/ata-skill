# STATUS.md 写法

`docs/STATUS.md` 记录项目的当前状态：当前主线、还没结束的任务卡、阻塞、暂停的主线和授权。新会话的 master 只读它就能接手，路由也只看它「当前主线」的第一行。由 master 维护，worker 不改。

本文只写当前状态，不写历史：能查 Git 或任务卡的，不在这里重复。

## 模板

```markdown
# 项目状态

> 由 master 维护，事件发生时当场更新：派工、验收、返工、阻塞变化、主线状态变化。
> 只写当前状态，控制在约 60 行以内；历史查 Git（验收提交以 `T-###:` 开头）。
> 与 Git 或实际文件冲突时，以后者为准，立即修正本文。

下一个卡号：T-001 · 下一个决定号：D-001 · 最近更新：YYYY-MM-DD

## 当前主线

<主线名> · 规划中|施工中 · 计划：<路径>
<一两句：当前的任务目标，进行到哪一步，下一步做什么>
...

## 任务卡

- T-### ：
  当前状态：进行中|返工中|受阻|挂起；
  任务目标：一两句话概括<这一卡在做什么>。

- T-### ：
  当前状态：进行中|返工中|受阻|挂起；
  任务目标：一两句话概括<这一卡在做什么>。

...

## 阻塞

- T-### ：
  阻塞原因：<卡在哪里> ；
  当前安排：<对这张阻塞的任务卡的暂时处置>。

...

## 暂停的主线

- <主线名> 
  断点：<基线提交>；
  原因：<...>；
  恢复条件：<...>；
  对应计划：<路径>。
  
...

## 授权

- 推送：无长期授权
- <操作>：<范围>（<日期>，<条件>）

```

## 各节写法

**当前主线**：第一行是路由用的，格式固定：

| 情况 | 第一行 |
|---|---|
| 初始化中 | `初始化` |
| 一条主线收口了，下一条还没定 | `待定` |
| 规划中 | `<主线名> · 规划中 · 计划：<路径>`，计划还没写时路径写「待写」 |
| 施工中 | `<主线名> · 施工中 · 计划：<路径>` |

第二行起用一两句写进行到哪一步、下一步做什么。

**任务卡**：每张还没结束的卡一条，写 `T-###`、当前状态和任务目标。「当前状态」的取值：

- `进行中`：已派发，worker 在做；
- `返工中`：已派返工项；
- `受阻`：worker 停下了，等用户或等前置条件，同时在「阻塞」里写清处置；
- `挂起`：随主线暂停而挂起，恢复条件写在卡片里。

「任务目标」一两句说清这张卡在做什么。卡片验收或取消后删掉这一条。

**阻塞**：每条写清「阻塞原因」和「当前安排」。「原因」写卡在哪里、需要谁做什么；「安排」写对这张卡的暂时处置。

**暂停的主线**：每条写清主线名、断点、原因、恢复条件和对应计划。「断点」写基线的提交，恢复时以它为准；「对应计划」写本主线计划文档的路径。交付项的完成情况在计划里，不复述。恢复后删掉这一条，主线回到「当前主线」。

**授权**：写明用户授权的范围、条件和日期，例如「每张卡验收提交后可以推送（YYYY-MM-DD）」。授权范围之外的操作仍按 master.md 2.3 问用户。

没有内容的节写「无」，不删节，这样读的人能确认这一项已经检查过。

## 不写什么

- 已完成的任务和提交流水：查 Git。
- 决定的理由：在 `docs/decisions.md`。
- 计划的目标、范围和交付项：在计划文档，这里只写路径。
- 任务的要求和汇报：在任务卡。
- 查不清、但还不阻塞的现象：记在对应任务卡的「偏离与疑点」里，或者开一张调研卡，不在本文挂着。
