# STATUS.md 写法

`docs/STATUS.md` 记录项目的当前状态：当前主线、进行中的任务、待用户决定的事、阻塞和授权。新会话的 master 只读它就能接手，路由也只看它「当前主线」的第一行。由 master 维护，worker 不改。

## 模板

```markdown
# 项目状态

> 由 master 维护，事件发生时当场更新：派工、验收、返工、阻塞变化、用户决定、主线状态变化。
> 只写当前状态，控制在约 60 行以内；历史查 Git（验收提交以 `T-###:` 开头）。
> 与 Git 或实际文件冲突时，以后者为准，立即修正本文。

下一个卡号：T-001 · 下一个决定号：D-001 · 更新：YYYY-MM-DD

## 当前主线

<主线名> · 规划中 · 计划：待写
<一两句：进行到哪一步，下一步做什么>

## 进行中任务

无

## 待用户决定

无

## 阻塞

无

## 暂停的主线

无

## 遗留问题

无

## 授权

推送：无长期授权
```

## 各节写法

- **当前主线**：第一行固定为 `<主线名> · 规划中|施工中 · 计划：<路径>`，计划还没写时路径写「待写」。初始化期间写 `初始化`；一条主线收口、下一条还没定时写 `待定`。第二行起用一两句写进行到哪一步、下一步做什么。
- **进行中任务**：每张卡一行，`T-### · <状态> · <一句话>`。卡片验收或取消后删掉这一行。
- **待用户决定**：每条写清要决定什么、有哪些选项、你的推荐。用户决定后删掉，决定本身记进 `docs/decisions.md`。
- **阻塞**：写清卡在哪里、需要谁做什么。
- **暂停的主线**：写断点：基线提交、已完成和未完成的交付项、挂起的卡、恢复条件。
- **遗留问题**：只记还没查清、但不阻塞的现象，附证据位置。查清后转进对应的计划或任务卡，再删掉。
- **授权**：写明用户授权的范围和日期，例如「每张卡验收提交后可以推送（YYYY-MM-DD）」。

没有内容的节写「无」，不删节，这样读的人能确认这一项已经检查过。

## 不写什么

- 已完成的任务和提交流水：查 Git。
- 决定的理由：在 `docs/decisions.md`。
- 计划的目标、范围和交付项：在计划文档，这里只写路径。
- 任务的要求和汇报：在任务卡。

## 补建

已经在用 ata 的项目缺少 STATUS 时（例如从旧版 ata 升级）：从总计划的路线图、当前主线的计划文档和 `git log` 判断当前主线和进行中的工作，按模板写好，向用户确认后提交。卡号和决定号从项目里已用过的最大编号往后接。
