# decisions.md 写法

`docs/decisions.md` 记录用户确认、会约束后续工作的决定，以及做出决定的理由。只追加，不改写：推翻一个决定时追加新条目，原来的理由还留着，后来的人能看懂当初为什么那样做。由 master 维护。

## 记什么

- 记：用户确认的产品取舍、范围、技术路线、验收标准、协作约定；推翻已确认内容的决定（`workflows/ad-hoc.md` 的 L2）。
- 不记：实现细节、还没确认的倾向、从代码或 Git 能直接查到的事实。
- 用户做出决定时当场追加，同时修改受影响的计划文档（master.md 5.2）。

## 模板

```markdown
# 决定记录

> 只追加，不改写。记录用户确认、会约束后续工作的决定。
> 被推翻时追加新条目，并在旧条目标题后标注「已被 D-### 取代」。

## D-001 · YYYY-MM-DD · <标题>

- 决定：<内容>
- 理由：<为什么>
- 影响：<据此修改了哪些文档>
```

## 写法

- 编号取 STATUS 的「下一个决定号」，追加后把它加一。
- 「决定」写结论，不复述讨论过程。
- 「理由」写用户的考虑和取舍依据，这是这份文档最有价值的部分。
- 「影响」写据此修改了哪些文档，没有就写「无」。
- 推翻旧决定：新条目在「决定」里写明取代 D-###；旧条目只在标题后标注「已被 D-### 取代」，正文不动。
- 初始化时先只建标题和说明，对齐方向时确认的决定逐条追加。
