# 速记本写法

`docs/scratchpad.md` 是 master 和用户讨论时的速记本：每次用户确认一条，当场记录，上下文被压缩后讨论还能接续。内容整理进正式文档后删除对应板块；全部清空并据此写成的文档通过用户审查后，整体归档冻结。

## 模板

速记本在进入多轮讨论阶段前由 master 建好骨架，根据本次讨论涉及的内容划分板块，一个板块对应一类需要确认的信息：

```markdown
# 速记本

> 讨论中已确认、还没整理进正式文档的内容。由 master 维护，用户也可以直接改。

## <板块名>

范围：<本板块要确认的是哪类信息>

待确认事项清单：
- [ ] <事项>
- [ ] <事项>
...

讨论记录（已确认项）：
- Q：<问了什么>
  A：<用户的回答或现在的方案> 
  理由：<理由>
- Q：<问了什么>
  A：<用户的回答或现在的方案> 
  理由：<理由>
...

## <板块名>

...

```
## 板块划分

- 板块在建立速记本时一次划好，覆盖本次讨论要涉及的所有信息类型；讨论中发现缺少某类时可以追加。
- 一个板块对应一类信息，不对应单个问题；同类问题归入同一板块。板块数不细分到单个问题粒度。

每个板块的「待确认事项清单」列的是「确认了这些事项，这个板块就算讨论完」，而不是要问的问题列表。确认一项，在清单里打勾；整个板块打完，这个板块结束。

检验：「这个清单全部打勾后，这部分信息就够用了吗？不够，就补充条目。」

## 讨论记录（已确认项）

- 用户回答或确认一条，在同一轮回复里当场写进去，不攒到讨论结束。
- 理由的填法：用户给了解释 → 写用户的理由；用户选了推荐方案但没解释 → 写推荐时给的理由；用户选了其他方案且没解释 → 写「无」。
- 约束后续工作的决定，直接追加进 `docs/decisions.md`，不在这里重复；拿不准算不算决定的，先记在这里，整理时再分。

检验：「新的 master 读完速记本，会把用户已经回答过的问题再问一遍吗？」

## 归档冻结

依据速记本写成的文档通过用户审查后归档：

1. 将 `docs/scratchpad.md` 完整复制到 `docs/archive/scratchpad_<主线名>.md`，归档文件只读，不再修改；
2. 清空 `docs/scratchpad.md`，重置为空模板，准备下一次讨论。

提前归档是错误的：讨论结束和文档通过用户审查，两个条件都满足后才归档。

## 不写什么

- 讨论过程和对话原文；
- 已整理进正式文档的内容；
- 当前状态（在 STATUS）。
