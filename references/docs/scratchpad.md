# 速记本写法

`docs/scratchpad.md` 是 master 和用户讨论时的速记本：用户确认一条，当场记下来，上下文被压缩以后讨论还能接上。它只是中转，内容整理进正式文档后就删掉。初始化时建立，由 master 维护，用户也可以直接改。

## 模板

```markdown
# 速记本

> 讨论中已确认、还没整理进正式文档的内容。由 master 维护，用户也可以直接改。
> 整理进正式文档后，删掉对应的内容。

当前没有内容。
```

一个话题一节：

```markdown
## <话题> · 去向：<之后整理进哪份文档>

已确认：
- <结论>；理由：<不明显时写>
- 不做<方案>；理由：<…>

待讨论：
- <问题>；推荐：<…>
```

## 写法

- 用户确认一条，就在同一轮回复里写进去，不攒到讨论结束。
- 「已确认」一条一行，只写结论。用户否决的方案也记下，写明理由，免得压缩以后又提一遍。
- 「待讨论」每条附上你的推荐；用户确认后，挪到「已确认」。
- 约束后续工作的决定，照常直接写进 `docs/decisions.md`，这里不重复。拿不准算不算决定的，先记在这里，整理时再分。
- 不用每改一次就提交，随下一次文档提交一起提交。

检验：「如果现在丢失全部上下文，新的 master 读完速记本，会把用户已经回答过的问题再问一遍吗？」

## 读取和清理

- 会话启动和上下文压缩后都读（master.md 第 3 节）。
- 一个话题写进正式文档（计划、决定、规格、任务卡）后，删掉这一节。
- 超过约 50 行，说明该整理了：把能定稿的话题先写进正式文档。

## 不写什么

- 讨论过程和对话原文。
- 已经写进正式文档的内容。
- 当前状态：在 STATUS。
