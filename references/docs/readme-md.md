# README.md 写法

`README.md` 是给使用者和贡献者看的仓库入口：项目能做什么，怎么安装、运行和验证。项目有了可以交给别人使用的功能时再建。使用方式发生变化时，由引起变化的那张任务卡，或者主线收口时的一张卡同步更新。

## 模板

```markdown
# <项目名>

<一两句：是什么，能做什么>

## 当前能力

- <已经交付、可以使用的功能>
- 限制：<使用者需要知道的边界>

## 安装与配置

<前置条件、安装步骤、配置项>

## 使用

<入口命令和最常用的用法>

## 开发与验证

<运行测试和检查的命令>

## 文档

- <使用者和贡献者需要的文档入口>
```

## 各节写法

- 只写已经交付的。写进去的每条命令，都在当前代码上实际跑通过。
- **当前能力**：从使用者的角度描述能做什么，不写实现。
- **限制**：会影响使用的边界，例如支持的平台、还没处理的情况。
- **文档**：只列使用者和贡献者用得上的；项目结构最多用几行说明顶层目录，文件职责交给源码地图。

检验：「一个新用户只照着 README 操作，能装好、跑起来、跑通验证吗？」

## 不写什么

- 还没交付的功能的用法；路线图：在总计划。
- agent 协作规则：在 `AGENTS.md`。
- 任务和进度：在 STATUS。
- 逐个文件的说明：在源码地图。
- 开发经过和更新流水：在 Git 历史。
