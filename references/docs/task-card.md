# 任务卡写法

任务卡（`docs/tasks/T-###.md`）是 master 派工和验收的依据。本文写给 master：卡片的位置、写法、返工和生命周期，第一次写卡前读。worker 怎么执行和汇报，写在 `references/worker.md`。

## 位置与编号

- 卡片放在 `docs/tasks/T-###.md`。编号全局递增，取 STATUS 记录的「下一个卡号」，用过的编号不再复用。
- 验收提交的信息以 `T-###:` 开头，这样 `git log --oneline` 就是完成记录。

## 卡片模板

```markdown
# T-###：<标题>

状态：执行中 · 主线：<主线名> · 交付项：<计划里的条目> · 风险：常规 | 高

## 目标

<完成后能观察到什么，1～3 句>

## 必读

- <路径#章节>：<为什么读>

## 写入范围

- 允许：<文件或目录>
- 禁止：<本卡特有的越界风险>

## 做法与约束

- <契约、必须遵守的规范条款、已知的坑、关键做法>

## 完成标准

- <可观察的结果>
- 验证：`<命令>`
```

使用任务分支或 worktree 时，在状态行下面加一行：`分支：<名> · 路径：<worktree> · 基线：<派发时的提交>`。

写法：

- worker 对每张卡都遵守的约定写在 `references/worker.md`，包括：卡片是任务的唯一依据、Git 只读、只改写入范围、什么时候停下交回、验证命令在最终状态运行、汇报写在卡片末尾。卡片里不重复这些约定。
- 篇幅跟着判断难度走。计划里写过的内容，给路径和章节，不复述。
- 「禁止」只写本卡特有的越界风险，例如相邻的共享文件；没有就删掉这一行。
- 「做法与约束」写 worker 自己判断不了的内容。这是卡片最有价值的部分，worker 施工的质量主要取决于它。
- 「完成标准」写可观察的结果和验证命令。worker 只拿这张卡，要能自己判断做完了没有。审查、调研卡写明要产出什么清单。
- 涉及数据迁移或删除、安全、公共接口或跨模块契约、发布流程，或失败代价大时，风险标「高」。它决定验收时是否重跑（master.md 5.6）。
- 有明显收益时，才写需要 worker 使用的 skill。
- 卡片超过约 80 行时，检查是否在复述 worker.md 的约定或计划，或者替 worker 写了它本来就会做的步骤。

## 返工

返工沿用原卡号。master 在卡片末尾追加：

```markdown
## 返工 1 · YYYY-MM-DD

- 问题：<现象>；证据：<位置>；要求：<怎么改>
- 验证：<需要补跑的命令；不写就沿用完成标准>
```

worker 处理后追加「第 2 轮汇报」。

## 生命周期

卡片状态只由 master 修改：

| 状态 | 何时 |
|---|---|
| 执行中 | 派发 |
| 返工中 | 追加返工 |
| 挂起 | 主线切换时暂停；卡片写明恢复条件 |
| 已完成 | 验收通过 |
| 已取消 | 决定放弃；STATUS 记下原因后删除卡片 |

- **派发**：写卡，在 STATUS 登记这张卡并把下一个卡号加一，提交（`docs: dispatch T-###`），然后告诉用户转手的话：「你是 ata 的 worker。读取 `docs/tasks/T-###.md` 并执行。」每张卡开一个新的 worker 会话：卡片已经是完整的交接，一个会话连续接卡只会带来频繁的上下文压缩和旧任务的干扰。返工时，原来的会话还在就接着用，转手的话不变。
- **验收记录**：通过时，master 在卡片末尾追加「## 验收 · YYYY-MM-DD」，写 2～4 行：结论、验收档位、判断审查的发现。不复述 worker 的证据。
- **删除**：已完成的卡保留到所在主线收口，再统一删除，之后从 Git 历史查（`git log -- docs/tasks/T-###.md`）。
