# 计划外工作：插入的需求、审查和计划变更

适用：用户提出当前主线计划之外的事。处理完回到原主线；原主线的 workflow 还在上下文里时，不用重读。

只需要回答、不需要改任何文件的问题，直接回答。

## 1. 判断大小

| 类型 | 例子 | 处理 |
|---|---|---|
| 小事 | 一次审查、一个 bug、一个调研问题 | 第 2 节 |
| 计划变更 | 增减需求、调整范围、推翻已确认的决定 | 第 3 节 |
| 大事 | 需要自己的计划，要派多张卡 | 第 4 节 |

拿不准时，告诉用户你的判断和理由，由用户决定。

## 2. 小事：一张卡，做完回主线

- 写一张卡，主线字段写「计划外」，在 STATUS 登记；验收同 `workflows/execution.md` 第 3 节。
- 审查和调研卡是只读的，产出发现清单或结论清单。哪些发现要改由你判断：改动另开卡，或并入当前主线；需要改计划的，按第 3 节处理。
- 环境里有对应的独立 skill（例如文档审查）时，可以在卡里要求 worker 使用。

完成标准：卡片已验收；STATUS 的当前主线没有变化。

## 3. 计划变更：按影响分级，只做该级要求的最少动作

| 级别 | 情况 | 最少动作 |
|---|---|---|
| L0 | 实现细节变化，不改目标、范围、契约和验收 | 直接执行，在汇报或验收记录里记一句 |
| L1 | 改一张卡的需求、写入范围、契约或验收 | 修改卡片，在卡片末尾追加一行变更说明，告诉用户转手 |
| L2 | 推翻已确认的内容：decisions 里的决定、计划的目标或范围、已验收的行为 | 先经用户确认；decisions 追加取代旧条目的新决定；修改该事实的唯一归属文档；逐一处理受影响的卡和文档 |
| L3 | 暂停当前主线，转做另一件事 | 第 4 节 |

- 拿不准级别时，按高一级处理。
- 删除或迁移已确认的内容时，逐条写明去向：迁到哪里、被哪条决定取代，或者确认作废。

完成标准：变更涉及的文档互相一致，并且已经提交。

## 4. 大事：主线切换

1. 停止派发原主线的新卡。
2. 原主线进行中的卡，逐张三选一：
   - **收尾**：做到能验收的点，按正常流程验收；
   - **挂起**：让 worker 把本轮汇报更新到当前状态，你在卡片写明恢复条件，保留卡片；
   - **取消**：在 STATUS 记下原因后删除卡片；有价值的结论转入 decisions 或计划。
3. 在 STATUS「暂停的主线」记下断点：基线提交、已完成和未完成的交付项、挂起的卡、恢复条件。
4. 新主线成为当前主线，状态为规划中，在路线图里加一行，标为进行中；然后按 `workflows/planning.md` 规划。
5. 新主线收口后，和用户确认是否恢复暂停的主线。暂停的主线不标为已完成，取消的卡不写成已验收。

完成标准：STATUS 只有一条当前主线；每条暂停的主线都有能恢复的断点。
